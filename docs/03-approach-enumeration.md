## 方案 1: 纯 LLM Agent 模拟（Stanford Smallville 风格）

**核心方法**

每个 agent 是一个完整的 LLM agent，具有 Profile + Memory + Action 三模块。Agent 接收推荐的视频 feed，产出动作（观看时长、点赞、评论、分享、跳过、关注、创作内容）。直接套用 Agent4Rec 架构。

**1K -> 1B 缩放**

每个 agent 代表约 100 万用户的加权段。权重来自抖音用户分层（人口统计、活跃度、内容偏好聚类）。

**优点**
- 概念最简单
- 每个 agent 行为最丰富 —— 可捕捉复杂推理、品味形成、社交动态
- 输出直接可解释（自然语言决策解释）

**缺点**
- 最贵的方案（~$900/模拟天，按 3000 tokens/agent/step，100 steps/天，Claude 3.5 约 $3/M 计）
- OmniBehavior 记录的三大系统偏差：评分中心化、曝光偏差、动作简化
- 个体准确率仅约 12%（Beyond Believability）

**保真度预期**: 低。个体行为看似合理，但聚合分布会系统性偏向正面参与、中等评分、同质行为。

**参考**: Agent4Rec, OASIS, Stanford Generative Agents

## 方案 2: 原型聚类 Agent（AgentTorch 风格）

**核心方法**

将 10 亿用户聚类为 K 个原型（K=50-200，远小于 1000），每个原型有一个代表性 agent。1000 agent 预算按方差分配：高方差原型分配更多 agent。Agent 状态表示为张量（遵循 AgentTorch），GPU 加速并行模拟。

**1K -> 1B 缩放**

AgentTorch 通过张量化 agent 状态实现了单 GPU 840 万 agent。关键洞察：**原型方法优于个体模拟** —— 个体 LLM 调用引入噪声，原型聚合掉噪声后捕捉结构化模式。每个原型 agent 的输出按其人口份额加权，并做方差调整。

**优点**
- 计算高效
- 梯度校准比黑盒快 8300x
- 自然处理多样性覆盖问题
- 可微分特性允许端到端梯度流

**缺点**
- 丢失个体级丰富度
- 无法覆盖长尾用户行为
- 原型边界有些武断
- OpenCity 的 Group-and-Distill 有约 70% LLM 请求减少但一定质量降级

**保真度预期**: 中等（L4 60-70%），聚合分布较好，边缘案例弱。

**参考**: AgentTorch, OpenCity, PAARS

## 方案 3: 混合 LLM + 统计模型集成

**核心方法**

采用 LLM User Simulator (AAAI 2025) 的双模型架构：
- **逻辑模型**: LLM 提取商品特征、蒸馏用户情感、应用显式偏好规则
- **统计模型**: 从交互日志用传统 ML（GBT、CF embedding）捕捉行为模式
- 两个模型预测集成，统计模型提供分布级校准，LLM 提供推理级丰富度

**1K -> 1B 缩放**

统计模型可平凡扩展到 10 亿（embedding 操作）。LLM 仅服务 1000 代表性 agent。其余用户通过 embedding 相似度插值最近原型 agent。

**优点**
- 兼得两者优势：LLM 提供可解释性和处理边缘案例；统计模型提供分布精度和效率
- 论文证明集成可训练 RL 推荐策略
- 可量化保真度分数

**缺点**
- 工程复杂度高 —— 两条 pipeline、集成权重、兜底逻辑
- 统计模型受限于历史数据
- 需要大量特征工程

**保真度预期**: 中高（L4 65-75%）。对已知交互模式好，对全新 treatment 取决于 LLM 泛化。

**参考**: LLM User Simulator (AAAI 2025), SimUSER

## 方案 4: 离策略评估 (OPE) + LLM 增强

**核心方法**

用成熟的 OPE 方法 —— IPS、DR、SNIPS —— 从日志数据估计 treatment effect。LLM 增强：为每条日志交互，LLM 生成用户在替代 treatment 下的反事实行为。结合 OPE 的统计严格性和 LLM 的生成灵活性。

**1K -> 1B 缩放**

OPE 天然在全量日志上运行。LLM 仅为 1000 agent 子集生成反事实预测，用于去偏 OPE 估计。

**优点**
- 因果推断理论严格
- Netflix 生产系统使用 DR 估计器
- 无需模拟完整平台环境
- 提供置信区间而非点估计

**缺点**
- 需要倾向得分（propensity scores）
- treatment 与日志策略差距大时方差高
- LLM 反事实推理未经验证

**保真度预期**: 增量变化高（L4 70-80%），激进变化低。

**参考**: Netflix OPE, SYN-DIGITS, Open Bandit Dataset (ZOZO, 2600万记录)

## 方案 5: Fine-Tuned LLM 数字孪生

**核心方法**

遵循 UserMirrorer (ACL 2026)，在真实抖音用户交互数据上 SFT+DPO 微调轻量 LLM (7B)。两阶段微调：
1. 教师 LLM 为真实行为生成决策理由（隐式反馈 -> 显式偏好文本）
2. 不确定性 hard sample mining 选择最有信息量的训练样本

结果模型就是用户模拟器 —— 不是 prompt engineering persona，而是 persona 编码在权重中。

**1K -> 1B 缩放**

训练一个基座模型 + 1000 LoRA adapter（每个原型一个）。PersonaTwin 证明多层 prompt conditioning 可从单个基座产生 8500+ 个体数字孪生。

**优点**
- UserMirrorer 证明微调 7B 优于冻结 GPT-4（8 个领域）
- 根本绕过 RLHF "礼貌偏差"
- 推理时成本低（7B 比 GPT-4 便宜约 100x）
- 可本地部署（数据隐私）

**缺点**
- 需要大量真实数据（~10K 高质量样本/领域）
- 模型捕捉历史分布，对全新 treatment 泛化有限
- DPO 需要偏好对，构建困难
- 需定期重训（行为漂移）

**保真度预期**: 高（L4 70-80%），训练分布内准确。

**参考**: UserMirrorer (ACL 2026), PersonaTwin, VRAgent-R1

## 方案 6: 多层级 宏观+微观 模拟

**核心方法**

将模拟分两层：
- **宏观层**: 聚合统计模型（系统动力学）模拟人口级指标 —— 总 DAU、session 分布、内容供需平衡、热搜话题
- **微观层**: 1000 LLM agent 模拟个体行为，受宏观约束
- 两层交互：微观 agent 行为更新宏观状态，宏观状态约束微观环境

**1K -> 1B 缩放**

宏观模型用微分方程处理 10 亿级动态（非逐用户模拟）。微观 1000 agent 提供行为丰富度。类比气候模型中 GCM（全球环流）+ 区域降尺度。

**优点**
- 解决纯 agent 方案的根本限制：涌现宏观属性（网络效应、内容供需均衡、趋势动态）无法从 1000 agent 可靠产出
- OASIS 表明某些现象需要 10万+ 规模才涌现
- 宏观模型直接捕捉这些
- 计算可行

**缺点**
- 需要构建和校准两个独立模型
- 宏观-微观接口设计非平凡
- 两层间可能不一致
- 需要抖音生态的领域专家知识

**保真度预期**: 潜在最高（L4 75-85%），但校准困难。

**参考**: RecSim NG, AgentTorch

## 方案 7: 参数化模型 + LLM 增强

**核心方法**

为每种抖音交互类型建参数模型。例如：
- 观看时长 = 混合指数分布（即跳、部分观看、完播三个组分）
- 点赞概率 = logistic(完播率, 内容-用户亲和度, 时间段)
- 评论概率 = f(内容争议性, 用户表达性)

参数模型在真实数据上校准。LLM 用于：(a) 推理生成函数形式，(b) 冷启动用户，(c) 内容级特征（理解视频内容）

**1K -> 1B 缩放**

参数抽样可平凡扩展 —— 本质是有随机噪声的查找表。1000 agent 仅用于模型开发和持续校准。

**优点**
- 最快执行速度（参数抽样比 LLM 推理快数个数量级）
- 有明确的统计性质（置信区间、假设检验）
- 可整合进现有实验基础设施
- RecSim NG 已有 Google 生产使用

**缺点**
- 需要强领域专家指定正确参数形式
- 无法处理全新交互或参数族外行为
- 丢失涌现行为

**保真度预期**: 中等（L4 60-70%）。

**参考**: RecSim NG, Netflix 参数化模型

## 方案 8: 人口对齐 Persona 生成

**核心方法**

AgentA/B (Amazon, 2025) 开创的流程：
1. 从真实数据用降维+聚类挖掘行为聚类
2. 为每个聚类用 LLM 生成 rich persona（人口统计、偏好、活动模式、心理特征）
3. 分配人口权重
4. 500 treatment / 500 control 运行 AB 模拟
5. 用人口权重聚合结果

**1K -> 1B 缩放**

AgentA/B 表明正确构建的 persona + 1000 agent 可代表 10万+ 用户。PAARS 通过 KL 散度衡量，实现 2/3 方向一致。Stanford "1000 People" 论文用 1052 个深度访谈 persona 实现 85% 态度预测准确率。

**优点**
- 直接对标分布对齐目标
- AgentA/B 在电商场景有真实 AB 对比验证
- Persona 生成可利用抖音丰富数据

**缺点**
- 2/3 方向一致 = 1/3 错误，不够稳定
- Persona 质量强依赖聚类方法论
- 不建模实验期间的动态行为演化

**保真度预期**: 中等（L4 65-70%）。

**参考**: AgentA/B, PAARS, SocioVerse, Stanford 1000 People

## 方案 9: 反馈闭环协同模拟

**核心方法**

将完整推荐生态作为共演化系统模拟：用户 agent 与真实（或忠实复制的）推荐模型交互，推荐模型基于 agent 交互更新参数，继而改变 agent 体验。捕捉关键反馈闭环。

**1K -> 1B 缩放**

用抖音推荐模型的 offline 模式，接收 1000 agent（按人口加权）的合成交互数据。推荐模型通过其学习参数隐式处理"10亿用户"级的动态。

**优点**
- 捕捉最重要、最难建模的动态：推荐塑造偏好，偏好塑造推荐
- RecInter 复现了品牌忠诚度和马太效应
- 可在影响真实用户前检测病态动态（filter bubble、echo chamber）

**缺点**
- 推荐模型每步需重训
- OmniBehavior 的 "persona 同质化"正反馈风险
- 需要接入生产推荐模型（或忠实副本）

**保真度预期**: 高（L4 75-85%），长期测试可能更高（因为反馈闭环效应正好是本方案的强项）。

**参考**: FLOW, RecInter (EMNLP 2025), TriRec, RecoWorld (Meta)

## 方案 10: 因果后校准层（可叠加到任意方案上）

**核心方法**

使用任意 LLM 模拟方案作为"原始模拟器"，叠加因果推断校准层。SYN-DIGITS (2026) 证明：校准层用合成控制方法估计 LLM 预测与真实人类的系统偏差，然后对新模拟做分布级修正。关键洞察：**LLM 偏差是结构化的、可预测的** —— 在校准数据上测量后可修正。

**1K -> 1B 缩放**

校准层在聚合统计量上操作，零额外计算。需要历史校准数据（之前的真实 AB + 模拟 AB 配对）。

**优点**
- 模型无关 —— 可插入任何上游方案
- 分布偏差降低 50-90%
- 不改底层模拟器，只修正输出
- 持续积累改进

**缺点**
- 需历史 AB 数据冷启动
- 校准仅对见过的 treatment 类型有效
- 可能掩盖应在模拟层修复的问题

**保真度预期**: 在基础方案上 +5-15%。

**参考**: SYN-DIGITS, Netflix DR

## 方案 11: 可微分模拟 + 梯度校准

**核心方法**

整个模拟 pipeline 构建为可微分计算图（遵循 AgentTorch）。用户行为模型是可微分神经网络，loss 函数是模拟与真实 AB 结果的分布差异。梯度下降端到端校准所有参数。用轻量神经网络代理替代 LLM 调用（训练模仿 LLM 行为但可微分且快数个数量级）。

**1K -> 1B 缩放**

AgentTorch 单 GPU 840 万 agent（可微分模拟）。Agent 状态为 tensor `[N_agents, state_dim]`。所有操作向量化 PyTorch + XLA 编译。

**优点**
- 梯度校准比黑盒快 8300x
- 可微分特性允许直接优化模拟参数匹配真实结果
- GPU 硬件百万级 agent
- 自然接入 PyTorch 推荐模型训练 pipeline

**缺点**
- 丢失自然语言丰富度
- 代理模型可能不捕捉全部复杂度
- 需要大量工程（离散动作需 Gumbel-Softmax 松弛等）

**保真度预期**: 高（L4 75-85%），聚合分布直接优化匹配真实数据。

**参考**: AgentTorch

## 方案 12: 浏览器/UI 级 Agent 模拟

**核心方法**

遵循 SimGym (Shopify, 2026) 和 A/B Agent (KDD 2026)，agent 通过多模态 LLM（视觉+文本）与抖音真实界面交互。感知视频封面、标题、UI 元素，执行 UI 级操作（滑动、点击、观看、点赞、评论）。

**1K -> 1B 缩放**

1000 agent 各运行一个浏览器/app 自动化实例。人口级外推通过加权聚合。SimGym 并发 2000 浏览器 agent。

**优点**
- 最高的单 agent 保真度（SimGym 0.64 Pearson）
- 捕捉纯文本模拟遗漏的 UI 驱动行为（封面位置效应、滑动距离、视觉疲劳）
- A/B Agent 有专门的疲劳系统

**缺点**
- 极贵（SimGym 需 48 B200 GPU 跑 40万 session/天）
- 视频内容的多模态推理更贵
- 需维护抖音 app/web 的副本
- 速度受限于实时交互
- 1000 agent 到 10 亿需要极大外推

**保真度预期**: 最高（L4 80%+）。

**参考**: SimGym, A/B Agent

## 方案 13: World Model 模拟

**核心方法**

训练世界模型（神经网络预测 (state, action) -> next_state）。世界模型替代 LLM agent 和环境：给定用户 profile 和当前上下文，预测用户动作、推荐系统响应和状态转移。LLM 用于引导世界模型和处理 OOD 场景。

**1K -> 1B 缩放**

世界模型是快速神经网络前向传播，可扩展到任意规模。

**优点**
- 推理快（神经网络前向传播替代 LLM 生成）
- 自然捕捉时序动态和状态演化
- 可端到端训练
- 隐式学习推荐系统行为

**缺点**
- 需要大量高质量训练数据
- 黑盒，可解释性低
- 长期预测有复合误差
- 当前学界定位为 **2027+ 方向**（前沿研究）

**保真度预期**: 未知。理论潜力高，但验证不足。

**参考**: AlignUSER, RecoWorld (Meta)

## 方案 14: 多利益相关方生态模拟

**核心方法**

超越用户模拟，建模抖音生态全部利益方：用户、创作者、广告主、平台。每种利益方有自己的 agent 群体。TriRec 三方架构 + CreAgent 创作者长期模拟 + LLM-Augmented Digital Twin 四孪生架构。

**1K -> 1B 缩放**

1000 agent 预算跨利益方分配（如 600 用户 + 200 创作者 + 100 广告主 + 100 平台策略 agent）。每类用自己的缩放策略。

**优点**
- 最真实的生态系统表示
- 捕捉利益方间的策略互动（创作者调整策略应对算法变化、广告主竞争库存）
- TriRec 证明三方模拟可同时提升准确率和公平性

**缺点**
- 工程复杂度最高
- 每种利益方需不同 agent 架构
- 利益方间交互动态难验证
- 1000 agent 分摊后每类很少

**保真度预期**: 潜在最高，但最难校准。

**参考**: TriRec, CreAgent, LLM-Augmented Digital Twin
