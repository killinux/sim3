## 二、完成的工作

### 2.1 Beta 参数校准（P0 原目标）

**问题**：completion_rate 20.8%，真实 7.78%，偏高 2.67 倍。

**过程**：6 轮迭代（v7-v11），逐步调整 Band 3/4 的 Beta 参数和 skip_threshold。

| 参数 | 旧值 | 新值 | 效果 |
|------|------|------|------|
| Band 3 (interest 8-9) | `Beta(4,1.5)*0.35+0.55` | `Beta(4,1.9)*0.35+0.51` | 完播概率从 ~50% 降到 ~12% |
| Band 4 (interest 10) | `Beta(6,1.5)*0.2+0.8` | `Beta(5,2.0)*0.25+0.68` | 范围从 [0.8,1.0] → [0.68,0.93]，打破 100% 完播 |
| skip_threshold | `6 - int(affinity*5)` clamp [4,7] | `5 - int(affinity*5)` clamp [3,6] | 减少过度 skip |

**结果**：completion_rate 20.8% → 8.23%（20 agent 均值），接近真实 7.78%。

### 2.2 方差控制（扩展到 50 agent 后发现的新问题）

**问题**：50 agent 跑 5 次，skip_rate 从 19% 到 73%（标准差 19.5pp）。根因是 LLM interest_level 输出存在 batch-level correlation——同一次运行中所有 agent 同方向偏移。

**尝试失败的方案**：
- **Affinity prior blending**（混入品类亲和度先验）：先验太低（大部分亲和度 <0.1），把高 interest 尾部砍掉，completion 降到 ~1%
- **均值修正**（追踪 interest 运行均值，动态修正）：无法处理双峰分布（LLM 同时输出大量 2 和 9，均值正确但分布错误）

**最终方案——分位数映射**：
- 核心思想：LLM 排序可靠（A 比 B 有趣），但绝对值分布不稳定
- 做法：追踪 LLM 输出的经验 CDF，映射到预设的目标 CDF（TARGET_INTEREST_CDF）
- 不看绝对分数，只看相对排名，再用排名查目标分布
- 配合 temperature 0.7→0.2、低亲和度惩罚 -3→-1

**结果**：

| 指标 | 校准前 (std) | 校准后 (std) | 真实值 |
|------|-------------|-------------|--------|
| skip_rate | 53.5% (19.5pp) | 48.3% (2.2pp) | 47.98% |
| completion | 7.32% (4.1pp) | 8.69% (1.2pp) | 7.78% |
| avg_wr | 0.376 (0.124) | 0.414 (0.015) | 0.445 |

方差缩小 3-9 倍。

### 2.3 AB 方向一致性验证（P0 核心价值验证）

**设计**：用 KuaiRand 随机曝光 vs 正常推荐的已知方向作为 ground truth。
- Control：epsilon=0.8（80% 随机选视频），模拟随机曝光
- Treatment：epsilon=0.05（95% 按偏好选），模拟个性化推荐
- 50 agent，5 次运行

**过程中发现并修复的关键 Bug**：
- 首次运行方向**完全反转**
- 根因：`kuairand_loader.py` 视频 embedding 用 `hash(category) % 32`，用户 embedding 用 `CATEGORIES.index(category)`，编码不对齐
- 例：comedy 在用户侧 index=0，视频侧 index=28
- 个性化推荐依赖 dot product 匹配，编码不对齐等于随机匹配
- 修复后方向立即正确

**结果**：4/4 指标方向正确，5/5 次运行无翻转。

## 六、关键 Insights

1. **LLM 做判断，统计模型做生成**：LLM 擅长排序（A 比 B 有趣），但不能直接输出分布（watch_ratio 会集中在整数点）。混合架构是根本解法。

2. **分位数映射 > 均值修正**：LLM 的方差不仅仅是均值偏移，还有分布形状变化（双峰）。均值修正只能处理第一种，分位数映射两种都能处理。

3. **Embedding 对齐是隐性 bug**：用户和视频的品类编码不对齐时，个性化推荐实际上在随机匹配。这种 bug 不会导致报错，只会让 AB 方向反转，很难排查。

4. **先降方差再调均值**：方差太大时（std 19.5pp），每次跑结果差异太大，根本无法判断参数调整是往好的方向还是坏的方向。

5. **CDF 目标要预留余量**：分位数映射作用在 raw interest 上，但后续的疲劳惩罚和亲和度惩罚会额外推入 ~5% 的 skip。所以 CDF 中 skip 目标设 43% 才能达到实际 48%。
