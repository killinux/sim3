# AB 方向一致性验证报告

> 日期：2026-05-24
> 版本：v12f + embedding 对齐修复
> 数据集：KuaiRand-Pure

## 一、验证目标

**核心问题**：模拟系统能否正确预测 AB 实验的方向？

分布对齐（skip_rate、completion_rate 对齐真实值）只是前提。真正的价值是：当推荐策略改变时，模拟能否预测出与真实数据相同方向的指标变化。

## 二、实验设计

### 2.1 利用 KuaiRand 构造已知方向 AB

KuaiRand 数据集包含两种数据：
- **随机曝光**（`is_rand=1`）：随机给用户看视频，不考虑偏好
- **正常推荐**（`is_rand=0`）：推荐算法根据用户偏好选择视频

真实数据中的已知方向（正常推荐 vs 随机曝光）：

| 指标 | 随机曝光 | 正常推荐 | 变化 | 方向 |
|------|---------|---------|------|------|
| avg_watch_ratio | 0.445 | 0.475 | +6.6% | ↑ |
| skip_rate | 47.98% | 32.17% | -32.9% | ↓ |
| completion_rate | 7.78% | 21.12% | +171% | ↑ |
| like_rate | 0.48% | 1.77% | +269% | ↑ |

**预期**：个性化推荐 > 随机曝光，所有参与指标都更好。

### 2.2 模拟实验配置

| 参数 | Control（模拟随机曝光） | Treatment（模拟个性化推荐） |
|------|----------------------|------------------------|
| epsilon | 0.8（80% 随机选择） | 0.05（5% 探索） |
| diversity_weight | 0.8（80% 按热度） | 0.1（90% 按偏好匹配） |
| Agent 数 | 25（50% of 50） | 25（50% of 50） |
| 每 Agent 视频数 | 15 | 15 |

共 5 次运行，不同随机种子。

## 四、过程中发现并修复的 Bug

### 4.1 Embedding 对齐 Bug

**问题**：首次运行时方向完全反转（1/4 指标匹配）。

**根因**：`kuairand_loader.py` 中视频 embedding 使用 `hash(category) % 32` 编码品类位置，而 `surrogate_recsys.py` 中用户 embedding 使用 `CATEGORIES.index(category)` 编码。两者完全不对齐。

```
用户侧: comedy → index 0 (CATEGORIES 列表位置)
视频侧: comedy → index 28 (hash("comedy") % 32)

dot product 算出来的不是品类匹配度，而是随机噪声！
```

**影响**：个性化推荐（低 epsilon，高 embedding 权重）实际上是在随机匹配，效果比真随机更差。

**修复**：视频 embedding 改用 `CATEGORIES.index(category) % embedding_dim`，与用户 embedding 对齐。

**注意**：`content_pool.py` 的合成视频没有这个 bug（用的是 `centroid[i % embedding_dim]`），只有 KuaiRand loader 的真实视频有。

## 五、结论

| 验证项 | 结果 |
|--------|------|
| 方向一致性 | ✅ **4/4 指标全部正确** |
| 运行稳定性 | ✅ **5/5 次运行无翻转** |
| 效应量准确度 | ⚠️ 幅度偏差较大，需后续校准 |

**AB 方向验证通过**。模拟系统能够正确预测：个性化推荐比随机推荐带来更高的参与度。这验证了系统的核心价值——可以在 AB 实验上线前，通过模拟预测策略变化的方向。
