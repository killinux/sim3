# 推荐的 Top 3 组合方案

## 推荐方案 A: 混合多层架构 + 因果校准

**组合**: 方案 3（混合LLM+统计）+ 方案 6（多层级）+ 方案 10（因果校准）

**定位**: 最务实的路径，3-6 个月内可投产

**预估保真度**: L4 符号一致 75-85%

**预估成本**: 微调 ~$500 一次，每次模拟 ~$50-200

### 架构

```
┌─────────────────────────────────────────────────────┐
│ Layer 0: 数据基座                                    │
│ ┌─────────────────────────────────────────────────┐ │
│ │ 1000 个用户原型 + 人口权重                        │ │
│ │ 特征: 人口统计 + 内容偏好 embedding +              │ │
│ │       活跃模式 + 社交图位置 + 创作行为              │ │
│ │ 方法: PAARS persona 挖掘 + 行为聚类               │ │
│ └─────────────────────────────────────────────────┘ │
│                                                     │
│ Layer 1: 宏观模拟模型                                │
│ ┌─────────────────────────────────────────────────┐ │
│ │ 系统动力学:                                      │ │
│ │   DAU = f(内容供给, 推荐质量, 外部事件, 季节性)     │ │
│ │   Session 分布 = 混合模型（真实数据校准）           │ │
│ │   内容供给 = f(创作者群体, 激励, 热搜话题)          │ │
│ │ 更新频率: 每模拟日一次                            │ │
│ │ 输出: 为 Layer 2 提供环境约束                      │ │
│ └─────────────────────────────────────────────────┘ │
│                                                     │
│ Layer 2: 微观 Agent 模拟 (1000 agents)               │
│ ┌─────────────────────────────────────────────────┐ │
│ │ 每 agent: fine-tuned 7B LLM (SFT+DPO)           │ │
│ │ 输入: persona + 最近30条交互 +                    │ │
│ │       当前feed(离线RecSys) + 宏观上下文            │ │
│ │ 输出: watch_duration, like, comment,              │ │
│ │       share, follow, skip                        │ │
│ │ AB分组: 500 treatment / 500 control              │ │
│ └─────────────────────────────────────────────────┘ │
│                                                     │
│ Layer 3: 统计插值                                    │
│ ┌─────────────────────────────────────────────────┐ │
│ │ 对 1000 agent 动作分布拟合混合模型                 │ │
│ │ 生成 10亿用户级分布估计 + 置信区间                  │ │
│ └─────────────────────────────────────────────────┘ │
│                                                     │
│ Layer 4: 因果后校准 (SYN-DIGITS)                     │
│ ┌─────────────────────────────────────────────────┐ │
│ │ 维护 {历史AB, 模拟AB} 配对校准数据集               │ │
│ │ 学习偏差函数: bias(metric, treatment, segment)    │ │
│ │ 输出: 校准后效果估计 + 置信区间                    │ │
│ └─────────────────────────────────────────────────┘ │
│                                                     │
│ Layer 5: 验证仪表盘                                  │
│ ┌─────────────────────────────────────────────────┐ │
│ │ L1-L4 指标自动计算                                │ │
│ │ 历史 AB 定期回放追踪校准漂移                       │ │
│ └─────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────┘
```

### 抖音场景处理

| 场景 | 处理方式 |
|------|---------|
| 短视频推荐 | Fine-tuned 模型训练在真实观看数据上，捕捉即跳/部分/完播模式 |
| 多种交互 | 每种动作类型独立输出头，可独立校准 |
| 内容创作 | 宏观层建模供给动态 + 部分 agent 专属创作者原型 |
| 社交图效应 | 稀疏矩阵维护关注关系，影响内容曝光 |
| 冷启动用户 | 50-100 个"新用户原型" agent，少历史多人口特征 |
| 时间变化 | 宏观层日/周/季节模式 + agent 级时间段条件化 |

## 推荐方案 B: Fine-Tuned 数字孪生 + 可微分校准

**组合**: 方案 5（Fine-Tune 孪生）+ 方案 11（可微分模拟）+ 方案 10（因果校准）

**定位**: 追求最高精度，适合有 GPU 资源的团队

**预估保真度**: L4 符号一致 80-90%（充足校准数据后）

**预估成本**: Phase 1 ~$2-5K, 每次模拟 ~$5-20

### 架构

```
Phase 1: 数字孪生构建（离线，一次性 + 定期刷新）

  Step 1.1: 原型发现
    聚类特征: 观看模式 + 参与率 + 内容偏好embedding
                + 社交特征 + 时间特征
    方法: 层次聚类 + silhouette 优化

  Step 1.2: 训练数据准备
    每原型采样 100-500 代表用户
    提取最近 90 天交互序列（~10K 交互/用户）
    教师 LLM (Claude/GPT-4o) 生成决策理由:
      "用户看了这个美食视频 45% 因为对美食内容有中等兴趣
       但视频节奏对其偏好来说太慢了"
    不确定性过滤: 教师置信度 < 0.7 的样本丢弃

  Step 1.3: 微调
    基座: Qwen2.5-7B
    SFT: 训练 (persona, context, action, rationale)
    DPO: 偏好对（看80% = preferred vs 3s跳过 = dispreferred）
    1000 LoRA adapters（每原型一个）

Phase 2: 可微分模拟引擎

  Step 2.1: 神经代理模型
    将 fine-tuned LLM 蒸馏为轻量 MLP (3层)
    输入: [user_embedding, item_embedding, context_features]
    输出: action_probabilities / watch_time_prediction
    MLP 可微分 → 支持梯度校准

  Step 2.2: AgentTorch 式张量模拟
    agent_state = tensor[1000, state_dim]
    模拟循环（可微分）:
      content_feed = recommendation_model(agent_states)
      actions = neural_surrogate(agent_states, content_feed)
      agent_states = update(agent_states, actions)

  Step 2.3: 梯度校准
    Loss = distribution_divergence(模拟指标, 真实AB指标)
    反向传播更新:
      - 神经代理模型参数
      - 人口权重参数
      - 噪声分布参数
    ≈8300x 快于黑盒校准

Phase 3: LLM 兜底

  代理模型不确定性高时 → 回退到完整 fine-tuned LLM
  典型回退率: 5-15%
  处理: 新内容类型、异常用户场景、OOD treatment
```

### 相比方案 A 的关键优势

可微分校准允许**持续自动改进**模拟保真度：有新的真实 AB 数据时，梯度下降直接优化模拟参数，无需人工调参。

## 推荐方案 C: 生态协同模拟 + 真实 RecSys 集成

**组合**: 方案 9（反馈闭环）+ 方案 14（多方生态）+ 方案 8（人口 Persona）

**定位**: 最雄心勃勃，适合长期投入的大型项目

**预估保真度**: 短期 L4 75-85%，长期测试可能更高

**预估成本**: 16-32 GPU, 5-8 人团队, 3-6 月

### 架构

```
┌─────────────────────────────────────────────────────┐
│                                                     │
│  Component 1: 用户 Agent (600个)                     │
│  ┌───────────────────────────────────────────────┐  │
│  │ Fine-tuned 数字孪生                            │  │
│  │ Persona + Memory(30条) + Fatigue System        │  │
│  │ 覆盖全谱系用户原型                              │  │
│  └───────────────────────────────────────────────┘  │
│                                                     │
│  Component 2: 创作者 Agent (200个)                   │
│  ┌───────────────────────────────────────────────┐  │
│  │ 博弈论信念机制 (CreAgent)                       │  │
│  │ Belief: 创作者对算法的"心智模型"                 │  │
│  │ Strategy: 话题/时长/风格/发布时间决策             │  │

│  │ 用户行为→RecSys更新→推荐变化→用户行为变化         │  │

│  │ 社交图: 关注关系随 agent 动作演化                │  │

└─────────────────────────────────────────────────────┘
```

### 为什么值得这个复杂度

推荐系统的"推荐塑造偏好"反馈闭环是最重要也最难建模的动态。对抖音来说：
- 算法变化不仅改变用户看到什么
- 还改变创作者做什么
- 继而改变可供推荐的内容
- 最终改变用户长期行为

**只有生态模拟能捕捉这个链条**。RecInter 已证明能复现品牌忠诚度和马太效应。

## 三个方案的对比与选择

| 维度 | 方案A 混合多层 | 方案B 数字孪生 | 方案C 生态协同 |
|------|-------------|-------------|-------------|
| **保真度** | 75-85% | 80-90% | 75-85% (短期) |
| **成本/次** | $50-200 | $5-20 | $200-1000 |
| **团队规模** | 2-3人 | 3-5人 | 5-8人 |
| **建设周期** | 3-4月 | 4-5月 | 5-6月 |
| **数据需求** | 行为日志+历史AB | 行为日志+标注数据 | 行为日志+RecSys沙箱 |
| **独特优势** | 最快可投产 | 最高精度 | 捕捉反馈闭环 |
| **主要风险** | LLM偏差未充分修正 | 微调数据质量 | 模拟不稳定 |
| **适合团队** | 小团队快速验证 | 有ML工程能力 | 大团队长期项目 |

### 推荐实施路径

**渐进式**: A → B → C

1. **先做方案 A** (3-4月): 快速验证思路，拿到第一批模拟结果
2. **叠加方案 B** (额外 2月): 用可微分校准提升精度
3. **叠加方案 C** (额外 3月): 加入创作者 agent + RecSys 集成

**无真实数据时**: 用 KuaiRand 数据集做概念验证，方案 A 的简化版
