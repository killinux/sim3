# 缩放方法与验证方法论

## 一、1K Agent -> 1B 用户的缩放方法

### 1.1 行为聚类 / 原型发现

**目标**: 将 10 亿用户聚类为 K 个行为原型，每个原型由若干 LLM agent 代表。

#### 推荐的两阶段聚类方法

1. **阶段一**: 在采样子集上用 HDBSCAN 发现自然聚类结构
   - HDBSCAN 不需要预设 K，能发现任意形状的聚类
   - 自动标记噪声点（异常用户）
   - 在采样 10-50 万用户上运行

2. **阶段二**: 在全量数据上用 Mini-Batch K-Means 分配
   - K 由阶段一的自然聚类数指导
   - Mini-Batch K-Means 可处理十亿级数据
   - 预期 K 在 500-2000 范围

#### 最优 K 值确定

- **Silhouette 方法**: 对行为数据最可靠
- 扫描 K = [100, 200, 500, 1000, 2000]，选轮廓系数最高的
- 实际中受限于 1000 agent 预算：K <= 1000

#### 短视频用户的聚类特征

| 特征类型 | 具体特征 |
|---------|---------|
| 观看模式 | 平均观看时长、完播率分布、日均观看量、session 时长 |
| 参与行为 | 点赞率、评论率、分享率、关注率、收藏率 |
| 内容偏好 | 内容品类偏好向量（从观看/点赞历史提取的 embedding） |
| 活跃模式 | 日活跃时段分布、周活跃模式、session 频率 |
| 人口统计 | 年龄段、性别、城市层级、设备类型 |
| 社交特征 | 粉丝数/关注数、社交图中心性 |
| 创作行为 | 是否创作者、发布频率、创作品类 |

#### 聚类不平衡处理

使用 **Neyman 最优分配**:
```
n_k (分配给聚类k的agent数) ∝ N_k × σ_k
```
- N_k = 聚类 k 的人口份额
- σ_k = 聚类 k 的行为方差
- 高方差聚类分配更多 agent

### 1.2 重要性加权 / Raking / 后分层

**目标**: 使 1000 agent 的加权分布对齐真实人口的边际分布。

#### Raking（迭代比例拟合）

**推荐方法**: Raking 可以同时对齐多个维度的边际分布，且只需要边际分布（不需要联合分布）。

**算法步骤**:
1. 初始权重 w_i = 1 / 1000
2. 对每个边际维度 d（年龄、性别、活跃度等）:
   - 计算 agent 在维度 d 各类别上的加权比例
   - 调整权重使加权比例匹配真实边际
3. 重复直到收敛

**关键约束**:
- 权重截断: cap 在中位数的 5x（防止极端权重）
- **Kish 有效样本量**: `n_eff = (Σw_i)² / Σ(w_i²)`
- 如果 n_eff 低于 400，估计变得不可靠
- 监控 n_eff 作为权重质量指标

### 1.3 加权 Agent 群体的方差估计

#### 推荐方法: Rao-Wu Rescaling Bootstrap

- 500+ 重复抽样
- 优于 Taylor 线性化（Taylor 一致性地低估方差）
- 1000 agent + 有效样本量 ~600-800 时，可检测 **2-5% 的相对 treatment effect**

#### 检测力分析

| 有效样本量 | 可检测的 Cohen's d | 可检测的相对效果 |
|----------|-------------------|----------------|
| 400 | >= 0.20 | ~5-8% |
| 600 | >= 0.16 | ~3-5% |
| 800 | >= 0.14 | ~2-4% |
| 1000 | >= 0.13 | ~2-3% |

## 二、模拟保真度验证方法

### 2.1 四层验证框架

| 层级 | 名称 | 指标 | 适用场景 |
|------|------|------|---------|
| **L1** | 微观级 | Precision/Recall/F1 per action | 调试单个 agent 行为 |
| **L2** | 分布级 | KL散度, JS距离, Wasserstein, EMD, MMD | 比较行为分布整体 |
| **L3** | 排序级 | Spearman 秩相关 | 多 treatment 排序一致性 |
| **L4** | 因果级 | AB 符号一致率 + Pearson 相关 | **金标准**：方向对不对 + 幅度准不准 |

### 2.2 分布比较指标详解

#### 何时用哪个指标

| 指标 | 适用数据类型 | 优点 | 缺点 |
|------|------------|------|------|
| **Wasserstein/EMD** | 连续有序（观看时长） | 尊重序关系，直观（"分布搬运距离"） | 高维时计算昂贵 |
| **JS 散度** | 离散类别（点赞/评论/分享） | 对称、有界 [0, ln2]，信息论基础 | 不尊重类别间距离 |
| **KL 散度** | 分布比较（单向） | 信息论标准 | 不对称，p(x)=0 处未定义 |
| **MMD** | 高维 embedding | 非参数，适合高维比较 | 核函数选择敏感 |
| **Chi-squared** | 加权类别数据 | 经典假设检验 | 需要 Rao-Scott 修正处理加权数据 |

#### 抖音特异性指标

- **观看时长分布**: 用 Wasserstein 距离（拟合混合指数 vs 真实分布）
- **各品类参与率**: 用 JS 散度（多类别分布比较）
- **Session 时长分布**: 用 Wasserstein
- **用户 embedding 分布**: 用 MMD

#### 量化分位数曲线（Model-Free Fidelity Assessment, 2025）

严格的统计框架:
1. 对模拟和真实分别计算分位数曲线 Q(p), p ∈ [0,1]
2. 分位数差 Δ(p) = Q_sim(p) - Q_real(p) 量化每个分位数的偏差
3. 模型无关，可处理连续和类别数据
4. 不需要假设分布形式

### 2.3 A/A 测试验证

**目的**: 在无 treatment 条件下验证模拟系统本身没有系统偏差。

**方法**:
1. 运行模拟 AB 但不施加任何 treatment（两组完全相同）
2. 预期效果应为零
3. 收集 p 值
4. 检验 p 值是否服从 Uniform(0,1)

**需要多少次 A/A 运行？**
- 最低 **1000 次** A/A 运行
- 要检测 5% ± 1% 的假阳性率，需要 **1825 次**
- 用 KS 检验或 Anderson-Darling 检验评估 p 值均匀性

**不通过 A/A 的系统不可信任。**

### 2.4 反事实评估方法

#### IPS（逆倾向评分加权）

```
V_IPS(π) = (1/n) Σ [π(a|x) / π₀(a|x)] × r
```
- π: 目标策略（treatment）
- π₀: 日志策略（control）
- r: 实际奖励
- 无偏但方差高

#### SNIPS（自归一化 IPS）

```
V_SNIPS(π) = Σ [w_i × r_i] / Σ w_i,  w_i = π(a|x) / π₀(a|x)
```
- 有轻微偏差但方差显著更低
- **推荐作为默认 OPE 方法**（最小误差，无需调参）

#### DR（双稳健估计器）

```
V_DR(π) = (1/n) Σ [r̂(x,a) + w_i × (r_i - r̂(x,a))]
```
- 如果倾向模型或奖励模型任一正确，则一致
- Netflix 生产系统使用

#### 基准数据集: Open Bandit Dataset (ZOZO)

- 2600 万条记录
- 提供真实 ground truth（已知最优策略）
- 可用于验证 OPE 估计器的准确性

## 三、LLM Agent 校准方法

### 3.1 微调方法比较

| 方法 | 优点 | 缺点 | 推荐场景 |
|------|------|------|---------|
| **SFT** | 最简单，有效，近期研究表明 SFT-based reward weighting 比 DPO 好 7.16% | 可能过拟合训练分布 | **推荐起步方案** |
| **DPO** | 不需要显式奖励模型 | 需构建偏好对（困难），训练不稳定 | 有清晰偏好对时 |
| **RLHF** | 最灵活 | 最复杂，需要奖励模型 + PPO | 有大量资源时 |

#### UserMirrorer 训练数据生成方法

1. 教师 LLM 为真实用户行为生成认知决策过程解释
2. 不确定性过滤：丢弃教师 LLM 置信度 < 0.7 的样本
3. SFT 阶段: 训练 (persona, context, action, rationale) 元组
4. DPO 阶段: 构建偏好对（观看 80% = preferred vs 3秒跳过 = dispreferred）

#### FineRob 最优上下文发现

- **~30 条近期行为**是最优上下文窗口
- 少于 30 条：信号不足
- 多于 30 条：引入噪声，反而降低性能
- "观察和记忆推理"（对比当前观察与过去行为）显著优于"角色刻板印象推理"（过度依赖 profile）

#### Per-Persona LoRA 微调

PersonaTwin 证明了通过 LoRA adapter 实现 per-persona 微调的可行性：
- 单个基座模型 + 8500+ LoRA adapter
- 每个 LoRA 编码一个用户群体的行为特征
- 推理时按原型加载对应 LoRA

### 3.2 系统偏差修正

#### OmniBehavior 三大偏差

| 偏差 | 表现 | 原因 | 修正方法 |
|------|------|------|---------|
| **评分中心化** | 评分偏向 3-4 分，缺少 1-2 分 | RLHF "礼貌偏差" | 微调绕过 RLHF；或后校准 |
| **曝光偏差** | Agent 过度服从推荐 | LLM 倾向于"配合" | 加入显式拒绝概率 |
| **动作简化** | Agent 缺乏犹豫/放弃模式 | LLM 追求效率 | 加入噪声/疲劳模型 |

#### RLHF 引入的正向偏差

- 约 **29-41%** 的正向偏差
- 表现为：Agent 比真实用户更积极参与、评价更高
- 修正：calibrated temperature（按原型校准）

#### SYN-DIGITS 后校准

1. 收集历史校准数据: {真实AB结果, 模拟AB结果} 配对
2. 学习偏差函数: `bias(metric_type, treatment_type, user_segment)`
3. 应用修正: `calibrated = raw_simulated - estimated_bias`
4. 效果: 分布偏差降低 **50-90%**

#### 推荐采样参数

- **Temperature**: 0.8（默认），按原型校准
- **Top-p**: 0.95
- 每个原型可以有自己的最优采样参数

### 3.3 成本优化

#### Token 成本估算（1000 agent，每模拟天）

| 配置 | 每步 tokens | 步数/天 | 总 tokens/天 | 成本/天 |
|------|-----------|--------|-------------|--------|
| GPT-4o | ~2500/agent | 100 | ~250M | ~$750 |
| GPT-4o-mini | ~2500/agent | 100 | ~250M | ~$37 |
| Qwen-72B (自部署) | ~2500/agent | 100 | ~250M | 算力成本 |
| Qwen-7B (自部署) | ~2500/agent | 100 | ~250M | 算力成本极低 |

#### 关键优化技术

| 技术 | 降低比例 | 来源 |
|------|---------|------|
| **Batch 推理** | 成本 -50% | vLLM 批处理 |
| **Group-and-Distill** | LLM 请求 -73.7%, tokens -45.5% | OpenCity |
| **Prompt 缓存** | 重复前缀 -90% | API provider 缓存 |
| **语义缓存** | 相似请求直接返回 | 自建缓存层 |
| **模型路由** | 成本 -60-70% | 简单决策用 7B，复杂决策用 72B |
| **AgentDiet** | 输入 token -40-60% | 轨迹压缩 |

#### 综合优化后成本估算

- API (GPT-4o-mini + 全部优化): **~$5-10/模拟天**
- 自部署 (Qwen-7B + 路由): **< $1/模拟天**（算力摊销后）
- 对比：一次失败的真实 AB 测试的机会成本 >> $10
